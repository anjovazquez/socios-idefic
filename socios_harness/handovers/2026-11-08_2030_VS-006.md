# Handover — VS-006

Date: 2026-11-08
Task: VS-006 — Alta de socio e invitación por email
Status: DONE

## Goal

El admin da de alta un socio con nombre y email y el sistema le envía una invitación con la identidad del club.

## What was implemented

- BD: `club_invitations` + `user_id`, `last_sent_at`, `send_count`; RPC `prepare_member_invitation` (admin del club: valida, detecta cuenta existente, audita `member_invited`), `attach_invited_member` (solo service role: pertenencia `invited`/`active` con nº de socio siguiente, bloqueando el club), `get_club_members`, `prepare_invitation_resend` (audita `member_invitation_resent`).
- Edge Function `invite-member` (alta y reenvío) sin dependencias npm: `_shared/supabase_rest.ts` (RPC y `generate_link`), `_shared/mailer.ts` (Resend / Mailpit / consola), `_shared/emails.ts` (email con logo, color y contraste del club; versión «ahora también eres socio»).
- Flutter: `ClubMember`, `MemberFailure`s, `MembersRepository`, casos de uso `GetClubMembers`, `InviteMember` (normaliza/valida), `ResendInvitation`; `SupabaseMembersRepository` (`functions.invoke` + mapeo de errores); pantalla `/club/members` (listado con nº y estado Invitado/Activo/Baja, «Nuevo socio», «Reenviar invitación»); acceso «Socios» en la portada para admin.
- `config.toml`: `otp_expiry = 86400`, `[edge_runtime.secrets]` locales. `DEPLOYMENT.md` con los secretos de staging. CI: job `edge-functions` (deno lint + test).

## Database changes

- RLS: sin cambios (todo vía RPC `security definer`; `attach_invited_member` solo `service_role`).

## Important findings

- El edge-runtime de este sandbox no confía en la CA del proxy y no puede descargar paquetes npm → las funciones se escribieron sin npm (también más ligeras en producción).
- Un `deno.lock` local hacía que el runtime intentara descargar dependencias: `lock: false`.
- Los enlaces de GoTrue devuelven tokens en el fragmento de `APP_URL`.
