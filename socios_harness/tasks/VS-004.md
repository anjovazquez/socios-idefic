# VS-004 — Identidad visual por club + DESIGN.md

Status: READY
Milestone: 0.1 Acceso multi-club
Refs: §20, RF-030, §16 Configuración

## Goal

Cada club tiene logo y colores, y la app se tiñe con la identidad del club activo.

## In scope

- Storage bucket `club-assets` (lectura para miembros del club y superadmin; escritura admin del club/superadmin).
- Pantalla Configuración (admin de club): nombre visible, logo, imagen, color principal y secundario, con previsualización.
- `ClubTheme` en presentación: `ThemeData` derivado de los colores (ColorScheme.fromSeed + contraste AA) aplicado a cabecera, navegación y selector.
- Selector de club con tarjetas de identidad (logo, nombre, color).
- Crear `DESIGN.md` en la raíz: tokens, tipografía, espaciados, componentes base (`ClubHeader`, `ClubCard`, estados vacíos), tono de voz.

## Out of scope

Carnet (VS-015), recibos (VS-019), PWA por club (fuera del MVP).

## BDD

```gherkin
Feature: Identidad visual del club

  Scenario: El admin cambia los colores
    Given soy administrador de IDEFIC
    When guardo color principal "#0B3D91" y subo el logo
    Then la cabecera y la navegación de IDEFIC usan esos colores y el logo

  Scenario: Cambio de club cambia la identidad
    Given Luis pertenece a IDEFIC y Club Demo
    When cambia a Club Demo
    Then la app muestra el logo y los colores de Club Demo

  Scenario: Contraste legible
    Given un color principal muy claro
    Then el texto sobre él se muestra en un color con contraste suficiente

  Scenario: Solo el admin edita
    Given soy socio de IDEFIC
    When intento cambiar la configuración visual
    Then el servidor lo rechaza
```
