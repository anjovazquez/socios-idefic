# VS-024 — Cancelación y cobro automático de la renovación

Status: TODO
Milestone: 0.6 Pago real y renovación automática
Refs: RF-014, RN-013, RF-012

## Goal

El socio puede cancelar la renovación antes del cargo; si no cancela, el sistema cobra automáticamente en la fecha prevista.

## In scope

- RPC `cancel_renewal(season_membership_id)` (socio dueño, solo antes del cobro, con hora del servidor) → `cancelled`, sin cargo.
- Cron `charge-renewals`: para cada renovación con aviso enviado, no cancelada, con método guardado y `charge_on <= hoy`, crea `payment` y lanza cobro off-session (idempotency key por season_membership).
- Fallo de cobro → `failed` + email "No hemos podido cobrar tu cuota" con enlace para pagar manualmente.
- Admin ve canceladas y fallidas en Pagos.

## BDD

```gherkin
Feature: Renovación automática

  Scenario: Cancelar antes del cargo
    Given Marta recibió el aviso y el cargo es el 1 de septiembre
    When cancela la renovación el 20 de agosto
    Then no se le cobra y su renovación queda cancelada

  Scenario: Cobro automático
    Given Marta no canceló y tiene tarjeta guardada
    When llega el 1 de septiembre
    Then se le cobran 50 €, el pago queda "Pagado" y su carnet 2027/2028 está activo

  Scenario: Cancelación tardía
    Given el cobro ya se realizó
    When Marta intenta cancelar
    Then el servidor lo rechaza y se le indica que contacte con el club

  Scenario: Cobro fallido
    Given la tarjeta de Marta caducó
    When se intenta el cobro
    Then el pago queda "Fallido" y Marta recibe un email para pagar manualmente

  Scenario: Sin doble cobro
    When el cron se ejecuta dos veces el mismo día
    Then Marta tiene un único cobro
```
