# VS-017 — Pagar la cuota (puerto de pagos + proveedor manual)

Status: DONE
Milestone: 0.5 Pagos
Refs: §9, RF-015, D-011

## Goal

Existe el modelo de pagos desacoplado del proveedor y un primer proveedor `manual` (efectivo/transferencia/Bizum) que el admin confirma.

## In scope

- `payments` (season_membership_id, amount_cents, currency, concept, status `pending|paid|failed|cancelled`, provider, provider_reference, paid_at, created_by), transiciones válidas forzadas en servidor.
- Al quedar pagado → `season_membership.status = active` (trigger o RPC atómica).
- Puerto de aplicación `PaymentGateway` (startPayment, getPaymentStatus) con adaptador `ManualPaymentGateway`.
- Socio: en su suscripción ve "Pendiente de pago" con instrucciones de pago manual configuradas por el club (IBAN/Bizum/texto en Configuración).
- Admin: "Registrar pago" (método, fecha, referencia) y "Marcar fallido/cancelado".

## BDD

```gherkin
Feature: Pago de cuota

  Scenario: Pago manual registrado
    Given Marta tiene la cuota 2026/2027 pendiente de 50 €
    When el admin registra un pago por transferencia de 50 €
    Then el pago queda "Pagado" y Marta pasa a socia activa

  Scenario: Transiciones inválidas
    Given un pago "Cancelado"
    When se intenta marcar como "Pagado"
    Then el servidor lo rechaza

  Scenario: El socio no se marca como pagado
    When Marta intenta registrar su propio pago
    Then el servidor lo rechaza

  Scenario: Importe en céntimos
    Then todos los importes se guardan como céntimos enteros
```
