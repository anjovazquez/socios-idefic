# VS-023 — Aviso previo de renovación

Status: TODO
Milestone: 0.6 Pago real y renovación automática
Refs: RF-013, RN-012

## Goal

Antes de cualquier cobro automático el socio recibe un aviso con temporada, importe, fecha de cobro y cómo cancelar.

## In scope

- Campos de temporada: `renewal_charge_on` (fecha de cobro) y `renewal_notice_days` (por defecto 15).
- `renewal_notices` (season_membership_id, sent_at, charge_on, amount_cents) — idempotente.
- Cron (pg_cron → Edge Function `send-renewal-notices`) que envía el email a renovaciones `pending_payment` con método guardado y sin aviso, en la fecha correspondiente (hora del servidor, `Europe/Madrid`).
- Texto: «Tu suscripción al Club X se renovará para la temporada 2027/2028 por un importe de 50 €. El cargo se realizará el 1 de septiembre. Puedes cancelar la renovación antes de esa fecha.» con enlace a Mi suscripción.
- Mi suscripción muestra "Próximo cargo: 50 € el 1 de septiembre".

## BDD

```gherkin
Feature: Aviso previo

  Scenario: Aviso enviado
    Given la renovación de Marta para 2027/2028 es de 50 € con cargo el 1 de septiembre y aviso 15 días antes
    When llega el 17 de agosto
    Then Marta recibe el aviso con temporada, importe, fecha y opción de cancelar

  Scenario: Sin aviso no hay cobro
    Given a Marta no se le ha enviado aviso
    Then el cobro automático no se ejecuta

  Scenario: Aviso único
    When el cron se ejecuta varias veces
    Then Marta recibe un único aviso
```
